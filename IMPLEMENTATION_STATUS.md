# 2.0 candidate — implementation status

## Added or modified in the actual existing application

- Smart Syllabus enabled for new papers by default; Full Book, half, quarter, custom modes remain available. Chapter selection, per-book-question exclusion, immutable published mapping with year/source reference and SHA-256 content signature, selected revision filtering, server checks of permitted question IDs and changed source content, shortage warning. Official source PDFs are not automatically mapped; administrator maps chapters/questions and confirms source reference. Existing bank-level chapter flags remain available for school-created content.
- Existing shared (super-admin) and private school library structures retained, including grades from early years to intermediate. Existing PDFs remain browser-local; extracted text/questions remain centrally stored as in original app. No populated official curriculum corpus supplied. Private local-only extracted-text/question library is not implemented.
- Full-page OCR default; no automatic rule-generated questions by default; bilingual and mathematical symbol cleaning improvement; canceled/failed read rejected; atomic page replacement and page validation; same-book retry within current upload session; incomplete books filtered out of builder; full upload check before structure publication. This is not a replacement for dedicated mathematical OCR. Scanned textbooks/diagram extraction have not been tested and extraction is still heuristic. Cross-reload resume and advanced local AI not implemented.
- New saved papers store full content, option order, answers and diagrams (server retrieves missing source images). Legacy reference-only records remain readable, not retroactively restored. Edits/deletion blocked once result session exists. Existing templates and print editor retained. Independent A/B/C/D version package, editable DOCX export and unified complete package ZIP are not newly implemented.
- Original dynamic OMR layout and scanner retained; ambiguous scans are unselected by default; duplicate roll detection, answer key completeness and explicit flagged-scan confirmation added. Pure score/layout tests pass. Real printed/camera scan testing, QR versioning, mobile capture and integrated/separate packaging remain unverified or not implemented.
- Added student and academic-year enrollment tables, administrator paste-from-Excel roster import, school-scoped APIs, result roster loading and stable student ID linking for new scores. Existing legacy scores are not automatically linked. Student promotion is supported by new academic-year enrollment using the same admission number. Full exam/attendance/subject enrollment lifecycle not implemented.
- Added finalized results centre with class, subject, student and calendar-year filters. Existing result reports retained. Pending marks distinguished in new drafts, objective/subjective totals server-calculated when provided, validation and finalization locking added. No new annual weighted aggregate, detailed section reports, grade revision/rechecking workflow, or advanced topic analytics. Legacy data cannot establish pending vs zero retroactively.
- Added school calendar events, confirmed/tentative dates, teaching-day/date-sheet suggestion and print. No official holiday feed, calendar grid or persistent advanced syllabus plans.
- Fresh account/role checks on server sessions, authorization for saved source questions and exercise relations, no persistent network API cache, school scoping for new data, final results lock. Not a complete penetration test; production rate limiting, audit trails, backup UI, full RBAC and concurrent workflow hardening remain pending.
- Added additive database schema, unexecuted additive SQL upgrade, isolated Docker test database configuration, synthetic seed script, test/setup/deployment documents, and 11 dependency-free unit tests. Full production build and DB/browser tests blocked by missing dependencies and unavailable network.

## Important decisions and unresolved requirements

- Preserve original Next.js/PostgreSQL/Prisma stack and billing/auth rather than rewrite. Hostinger plan not supplied; no MySQL migration.
- Demo bank only, not official PECTAA, Federal, KPTB or AFAQ content. Source documents and licensing still needed.
- No mandatory paid OCR/AI service; current OCR may require network to fetch language models. No actual AI provider integration added.
- Source snapshots use more DB space than previous ID-only storage; avoid large image crops. Sensitive network reads are no longer persisted in the old local cache, which increases network requests. PDF IndexedDB store retained.
- This release is a candidate for developer/staging testing, NOT a certified complete 2.0 or production-ready release.
